# UI / UX Specification

## 共通

モバイルファースト。

主対象:

- 320px〜430px

PCでも使用可能だが、スマホUIを無制限に横へ引き伸ばさない。

画面ヘッダーは原則:

- 画面タイトル
- 必要なアクション

のみ。

説明サブタイトルは不要。

操作成功のうち、画面に残す必要がなく、遷移後には結果だけを短く伝えるものはトーストで表示する。対象は設定保存、投稿とイベントの作成・編集・削除、招待URLのコピーとする。入力エラー、読み込み失敗、削除確認はトーストにせず、操作箇所の近くまたはモーダルに表示する。コメントや権限変更のように結果がその場で明確に反映される独立操作にはトーストを表示しない。

## Bottom Navigation

```text
タイムライン
近況
イベント
アルバム
設定
```

「＋追加」はBottom Navigationから独立させ、そのすぐ上の画面右下へ固定表示する。ownerとuploaderが押すと「写真・動画」と「イベント」を選択できる。viewerには表示しない。

Bottom Navigationのタブを押して画面を切り替えたときは、遷移先を画面先頭から表示する。ほかのタブのスクロール位置は引き継がない。

# Activity

公開投稿とコメントを新しい順に表示する。誰が、どの投稿に、いつ操作したかを表示し、タップするとPost Detailを開く。投稿を表す名称はCaptionではなくScene titleを優先し、Sceneがない場合はEvent title、どちらもない場合は「投稿」とする。リスト上部には「最後に見た時間」として、メンバーのアイコン、表示名、最終閲覧からの相対時間を横並びで表示する。閲覧行為は近況リストへ表示しない。

# Timeline

タイトル:

```text
タイムライン
```

Postは複数Mediaのまとまり。

現在のユーザーがまだ見ていないPostは、Media Grid上へ「未閲覧」バッジを表示する。Post Cardが自動既読になったらバッジを消す。

Media Gridの上には、投稿者のプロフィールアイコン、投稿者名、日付、Event title、Scene titleを表示する。投稿者名を最も強く、日付を小さく、Event titleとScene titleをアクセントカラーの補助情報として扱い、投稿者と投稿の分類を混同させない。TimelineではEvent titleとScene titleを`Event title ＞ Scene title`の順に表示し、Event titleにはカレンダーアイコンを付ける。EventとSceneのどちらもないPostでは分類の代替文言を表示しない。

日付は投稿者名の下へ表示する。撮影日時がある場合はカメラアイコンと撮影日、ない場合はアップロードアイコンと投稿日を表示し、読み上げでも日付の種類を区別する。Media Gridの下には「見た人」の両目アイコンと人数、コメントアイコンとComment総数を並べる。その下にCaptionを「ひとこと」として表示する。Commentがある場合は最新の1件をPost Cardに表示する。2件以上ある場合は、その下に「ほかのコメントを見る」を表示し、Post Detailへ移動できるようにする。総数はコメントアイコンの右に表示済みのため、この導線では件数を重複表示しない。

代表例:

```text
[投稿者アイコン] 翼
                 📷 8月30日
                 ドイツ旅行 ＞ Day 2
[ Media Grid ]

👀 3   ◯ 2

念願のポルシェミュージアムへ行けた

[コメント者アイコン] すごかったね！
ほかのコメントを見る
```

## Media Grid

1枚:
- 大きく1枚

2枚:
- 2分割

3枚:
- 大1 + 小2

4枚以上:
- 代表3枚 + `+N`

写真・動画をできるだけ大きく表示。

表示済みのthumbnailとpreviewは端末へ最大300件キャッシュする。originalとvideoに加え、アプリ本体のHTML、JavaScript、CSSはService Workerのキャッシュ対象外とし、ログアウト時にメディアキャッシュを削除する。PWA起動中は背景透過のアプリアイコンとアプリ名を画面中央に表示する。ブラウザでの読み込み中はアプリ名と読み込み状態を表示する。Service Worker更新時は新版へ切り替えて自動再読み込みする。

# Album

画面名のヘッダーは表示せず、年の前後移動と月タブを一体化して画面上部へ固定する。公開済みの写真・動画を撮影日時の新しい順にまとめ、月の代表Mediaを大きく、そのほかを3列gridで表示する。月タブの左端には、その年の全Mediaを3列gridで表示するグリッドアイコンを置く。月タブには件数を表示しない。選択色はBottom Navigationと同じテーマ別の色を使う。Mediaを押すとMedia Viewerを開き、閉じるとアルバムへ戻る。ボトムナビではイベントの右に配置する。

---

# Event List

表示順は進行中、予定、日付未定、終了とする。進行中は終了日が近い順、予定は開始日が近い順、日付未定は更新が新しい順、終了は終了日が新しい順に並べる。進行中と予定のカードには状態バッジを表示する。

各Eventカードの背景全面にCover Mediaを表示。

Eventカードの縦横比は16:9とする。

下部へdark gradient。

表示:

- Event title
- start/end date
- 写真数
- 動画数

必要以上のmetadataは表示しない。

---

# Event Detail

Eventだけに絞ったTimeline。

上部:

- 大きなCover
- Event title
- dates
- 写真数
- 動画数
- Post数

Cover下部のdark gradientは画像下端まで連続させ、最下部では画像色が線状に残らないよう完全な黒へ収束させる。

Coverは画面ヘッダーの下へ固定し、投稿一覧を手前の不透明なsurfaceとして配置する。スクロールすると、上端を角丸にした投稿一覧がCoverへ重なり、最終的にCoverを覆う。Cover画像自体は重なっている間も同じ位置を保つ。

Eventを管理できるユーザーには、Coverの下へ「投稿を追加」を表示する。Sceneの管理はEvent Editへ集約する。

Event Editではタイトル、日付、メモ、シーン、カバーの変更を画面内へ一時保持し、保存前にAPIへ反映しない。いずれかが変更された場合だけ、設定画面と同じ「変更を保存」ボタンをBottom Navigationの上へスライドインさせる。保存時はすべての変更を一括して反映する。利用者向けの表記には`Media`ではなく「メディア」を使う。

その下:

```text
Day 2 - シュトゥットガルト

Post Card
Post Card

Day 1 - フランクフルト

Post Card
```

Scene titleは必ず1行の文字列として扱う。
Event DetailではTimelineと同じPost Cardの構造を使い、Scene titleのグループ見出しを設けない。投稿者名と日付を最上位に表示し、Event titleはCoverと重複するため省略してScene titleだけを補助情報として表示する。Scene titleにはイベント用のカレンダーアイコンを付けず、Sceneがない場合は分類行自体を表示しない。

---

# Post Detail

ヘッダーには共通の画面タイトルを表示せず、戻るボタンと権限に応じた投稿メニューだけを置く。投稿者、Event、Scene、Media Grid、反応、撮影日、CaptionはTimelineと同じ視覚構造で表示する。Event titleにはカレンダーアイコンを付け、Scene titleは装飾のない補助行とする。

CaptionとComment一覧は同じsurface上に連続して配置し、背景色や太い帯で別の島に分けない。Comment一覧の開始位置は1pxの区切り線と余白で示す。

コメント投稿フォームはBottom Navigationの直上へ固定する。現在ユーザーのアイコン、コメント入力欄、送信ボタンを横並びにし、入力中やモバイルのsafe areaでもComment一覧の末尾を隠さない余白を確保する。

表示:

- Scene
- Event
- date
- uploader
- Media Grid
- caption
- seen by
- comments

コメントには本文、ユーザー名、日時に加えて、ユーザー名の左にプロフィール画像または表示名の先頭文字を使った丸いアイコンを表示する。

ownerとuploaderには右上に3点メニューを表示し、「編集」「削除」を配置する。編集ではEvent、Scene、Captionの変更に加え、写真・動画を追加・削除できる。写真・動画は合計30件まで、最低1件を残す。既存Mediaの削除は保存時に反映し、追加Mediaのアップロードに失敗した場合は失敗した項目だけ再試行できる。投稿自体の削除時は確認モーダルを表示し、写真・動画とコメントも削除されて元に戻せないことを明示する。投稿編集画面からSceneを新規作成でき、追加後はそのSceneを選択した状態にする。

TimelineやEvent DetailからPost Detailを開いたときは、遷移元のスクロール位置を引き継がず画面先頭から表示する。

Mediaを押すとMedia Viewer。

# Media Viewer

写真・動画が主役。

- 大画面表示
- 前後移動
- `5 / 18`
- thumbnail strip
- 撮影日時
- uploader
- Event / Scene / Post
- 保存

写真・動画は左右スワイプで前後へ切り替えられる。メディアは指の横移動に追従し、横移動が一定距離に達し、縦移動より明確に大きい場合だけ切り替える。切り替えに満たない場合は中央へ戻す。動画の再生バー操作はスワイプ判定から除外する。先頭と末尾では抵抗を付け、それ以上移動しないことを示す。

画像間の移動はブラウザ履歴へ追加しない。閉じる操作ではPost Detailへ戻り、その後の戻る操作でMedia Viewerへ戻らない。

外部共有ボタンは置かない。

# Post Create

順番:

```text
写真・動画
Event
Scene
ひとこと（Caption、任意）
投稿
```

Event / Sceneはoptional。

SceneはEvent選択時のみ。

Sceneを新規作成でき、追加後はそのSceneを選択した状態にする。

写真・動画の選択後はローカルでの準備中とアップロード中を区別して表示する。アップロード中に再試行ボタンを表示せず、失敗または中断した後だけ再試行導線を表示する。

不要:

```text
撮影日の扱い
写真・動画の撮影日時を...
```

これは内部仕様。

# Settings

最低限:

- 表示名
- LINE通知
- LINE連携状態
- アプリからの通知の受信状態
- メンバー一覧（ownerのみ。role・LINE通知ON/OFF）
- メンバーの管理（ownerのみ。権限設定・削除・招待URL発行画面への導線）
- ログアウト

LINE通知は、ベルアイコン、オン・オフの文言、状態に応じた説明を添えたトグルスイッチで切り替える。切り替え時はアイコンとスイッチをアニメーションさせるが、カード自体の背景色と枠線は変えない。「このごろ」のLINEアカウントを友だち追加していない場合は利用不可と明示する。アプリからの通知が受信可能な場合は状態だけを表示し、受信不可の場合だけLINEで「このごろ」アカウントをブロックしていないか確認するよう案内する。LINEでブロックするとWebhook受信後に受信不可・通知OFFへ自動更新し、友だち追加またはブロック解除後は受信可能へ自動更新する。解除時に通知を自動でONへ戻さず、ユーザーが明示的にONへ切り替える。

Bottom Navigationの5つ目は全role共通で歯車アイコンの「設定」とする。独立したメンバー画面は設けず、ownerの設定画面へメンバー一覧を統合する。「メンバーの管理」からさらに1階層下へ移動し、メンバーの権限設定・削除と招待URL発行を行う。削除前には、アクセスできなくなる一方で過去の投稿やコメントは残ることを確認画面で伝える。招待時の権限は、権限名と操作説明を含むカード型ラジオボタンから選択する。

設定項目は「プロフィール」「LINE」「表示」「メンバー」「その他」の見出しとカードを共通構造として使用する。表示名またはLINE通知が保存済みの値から変わった場合だけ、Bottom Navigationの上へ「変更を保存」ボタンをスライドインさせる。保存バーは追加ボタンより前面へ表示する。保存後はトーストを表示してボタンを収納する。選択時に即時反映するテーマ変更は保存ボタンの表示条件に含めず、テーマ設定は保存対象の項目より下へ分離する。テーマは比較しやすさを優先して3択カードを維持する。

設定項目の下部に背景透過のアプリアイコン、アプリ名、`package.json`を参照したバージョンを表示する。アプリ内でロゴを表示する場合は背景透過版を使用し、選択中のテーマに合わせて切り替える。ホーム画面へ登録するPWAアイコンはOS向けの背景付き画像を維持する。
