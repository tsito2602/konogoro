# このごろ — UI・UX仕様

画面の情報・操作・状態・遷移を定義する。視覚の数値は[デザインガイド](05_DESIGN_GUIDE.md)を参照する。

2026-09改訂: 「目標仕様 #番号」は後続Issueで導入する要求であり、現行実装済みではない。それ以外の既存機能は維持する。各Issueは[改訂記録](11_DESIGN_REVISION.md)と本書を起点に差分だけを実装する。

## 共通

モバイルファースト。

主対象:

- 320px〜430px

PCでも使用可能だが、スマホUIを無制限に横へ引き伸ばさない。

PC幅ではBottom Navigationを左側の常設ナビゲーションへ切り替え、メインコンテンツと操作領域を分離する。ownerとuploaderには左ナビ上部へ、通常のナビ項目と区切った目立つ追加枠を常時表示する。1024px以上でPC表示へ切り替え、本文は最大1280pxのキャンバス内へ配置し、画面タイトルと操作も同じ左右位置へ揃える。1024pxから1199pxでは無理に多列化せず広い1列または2列を使い、1200px以上では画面の用途に応じて補助領域を分離する。モバイルとタブレット幅では従来どおりBottom Navigationと1列の画面構成を使う。

PC表示では、Timelineは読みやすい幅の投稿列と未閲覧導線の補助列、Activityは最終閲覧者と履歴、Event Detailはカバー・概要と投稿、Settingsと管理画面は関連する設定群をそれぞれ別の列へ配置する。Event Listは3列、Albumの月表示は代表Mediaと一覧を分け、年表示は6列を上限とする。Post DetailはMediaと投稿情報・コメントを左右へ分ける。投稿作成画面は写真・動画の選択・確認領域と投稿内容の入力領域を2列にし、広い画面で操作が散らばらない情報密度にする。

固定表示するヘッダー、保存操作、トースト、Post Detailは左ナビゲーションと重ならず、PC側のメインキャンバスを基準に配置する。Skeletonも各PC画面の最終的なカラム構成と幅に合わせる。

画面ヘッダーは原則:

- 画面タイトル
- 必要なアクション

のみ。

説明サブタイトルは不要。

操作成功のうち、画面に残す必要がなく、遷移後には結果だけを短く伝えるものはトーストで表示する。対象は設定保存、投稿とイベントの作成・編集・削除、招待URLのコピーとする。入力エラー、読み込み失敗、削除確認はトーストにせず、操作箇所の近くまたはモーダルに表示する。コメントや権限変更のように結果がその場で明確に反映される独立操作にはトーストを表示しない。

データ取得中は、各画面の完成後の構造に近いSkeletonを表示する。画像やテキストの大きさを読み込み前から確保してLayout Shiftを抑え、共通の色とshimmer表現を使う。Skeletonの装飾要素は`aria-hidden="true"`とし、読み込み領域には`aria-busy="true"`と支援技術向けの読み込み中表示を設ける。`prefers-reduced-motion: reduce`ではshimmer animationを停止する。

## 初回利用案内

初めてログインしたviewerには、画面全体を使う6ページのガイドを表示する。家族だけで共有する場所であること、タイムライン、イベント、アルバム、コメントとお知らせ、LINE通知を、個人写真を含まない実画面に沿ったイメージと短い説明で案内する。投稿・管理機能は案内せず、設定から開いた場合も閲覧者向けの同じ内容を表示する。横スワイプ、前へ・次へボタン、左右矢印キーでページを移動でき、現在位置を真円のインジケーターで示す。右上の閉じるボタンは全ページで常に表示し、Escapeキーでも閉じられる。見出しは読点の直後で明示的に改行し、単語の途中では改行しない。ガイドを閉じても現在の目的地を変えない。表示済み状態は端末のlocal storageへ保存する。

viewerの利用中にホーム画面への追加案内を自動表示しない。設定の「使い方」から、初回ガイドと端末別のホーム画面追加手順を利用者が選んで再表示できる。local storageを利用できない場合も、各案内を閉じて主要操作を続けられることを優先する。

LINE Login開始時には、pathname、query、hashを同一origin内の戻り先として渡す。初期認証だけでなく、利用中にセッション切れを検知したエラー画面からの再ログインでも同じ戻り先を維持する。

## Bottom Navigation

```text
タイムライン
お知らせ
イベント
アルバム
設定
```

「＋追加」はBottom Navigationから独立させ、そのすぐ上の画面右下へ固定表示する。ownerとuploaderが押すと「写真・動画」と「イベント」を選択できる。viewerには表示しない。

Bottom Navigationのタブを押して画面を切り替えたときは、遷移先を画面先頭から表示する。ほかのタブのスクロール位置は引き継がない。

各項目の役割は次の通りとする。全roleで同じ項目名と並び順を使い、owner/uploaderの投稿・管理操作は従来どおり共通の追加ボタンと各詳細画面から提供する。

- タイムライン: 未閲覧の思い出への入口と、全投稿の一覧
- お知らせ: 新しい投稿やコメントの時系列の履歴
- イベント: 旅行やお出かけ単位でまとめた思い出
- アルバム: 写真・動画をイベント期間の年月から探す一覧
- 設定: 表示、通知、プロフィールと権限に応じた家族管理

「新着」は未閲覧投稿を指すように見え、タイムラインの「新しい思い出を見る」と目的が重複するため、Activityの表示名には「お知らせ」を使う。URLの`/activity`は既存の深いリンクとの互換性のため維持する。

実利用開始後は、viewerが未閲覧投稿を見る際にタイムラインではなく「お知らせ」を誤って選ぶか、「お知らせ」を写真一覧だと認識するかを確認する。5人以上のviewerへタスク確認を行い、2人以上が同じ箇所で迷った場合は、項目数の削減または名称の再検討をIssue化する。

# Activity

画面名は「お知らせ」とする。公開投稿とコメントを新しい順に表示する。誰が、どの投稿に、いつ操作したかを表示し、タップするとPost Detailを開く。投稿を表す名称はCaptionではなく見出しを優先し、見出しがない場合はEvent title、どちらもない場合は「投稿」とする。ownerには、リスト上部へ「最後に見た時間」として、メンバーのアイコン、表示名、最終閲覧からの相対時間を横並びで表示する。uploaderとviewerには最終閲覧時間を表示せず、APIからも返さない。閲覧行為はお知らせへ表示しない。お知らせは40件単位で取得し、末尾へ近づいたときに次の項目を自動で追加する。追加取得に失敗した場合は自動再試行を止め、既存の項目を残したまま再試行操作を表示する。

# Timeline

タイトル:

```text
タイムライン
```

Postは複数Mediaのまとまり。

イベント開始日を基準に、最初のPostと月が変わる位置へ`2026年9月`形式の年月見出しを表示する。開始日がないEventでは終了日を使う。Eventに属さないPostでは撮影日時、投稿日を順に使い、いずれもない場合は「日付なし」とする。年月見出しは次の年月見出しが来るまで画面ヘッダー直下へ固定し、同じ月のPostが続く間は繰り返さない。

タイムラインは落ち着いた背景の上へPost Cardを1列で並べ、カード間に余白を設ける。各Post Cardは余白と面でひとまとまりに見せ、必要な箇所のみ細い境界線を使う。Media Gridはカード幅いっぱいに表示する。左右の余白は写真の大きさを損なわない範囲に抑える。

現在のユーザーがまだ見ていないPostは、Media Grid上へ「未閲覧」バッジを表示する。Post Cardが自動既読になったらバッジを消す。

viewerのタイムラインでは、未閲覧Postがある場合に限り、上部へ合計件数と「新しい思い出を見る」ボタンを表示する。ボタンから新着閲覧フローへ移動する。

## 新着閲覧フロー

現行実装はPost Cardの50%以上を2秒表示すると自動既読を記録し、成功後に次へ進める。`UnreadPostsPage`には既に残り件数と失敗時の再試行がある。

**目標仕様 #46:** 既読は「投稿が画面に表示された」という受信確認であり、全写真の閲覧や動画の完走を保証しない。この意味を「見た人」と完了文言で一貫させる。メディア単位の既読や全件閲覧の強制は導入しない。

- 未閲覧投稿は公開日時の古い順。件数はサーバーの`view_histories`を正とする。
- 自動既読は2秒の連続表示を基本として維持する。画面より背の高いカードでも到達できる判定領域を定め、50%が永遠に見えず次へ進めない状態を防ぐ。非表示タブ・画面外の時間は数えない。
- 次へは2秒待ちを操作条件にせず、押した時点で現在投稿の既読を記録してから次を取得する。自動判定と重なっても重複処理しない。
- 通常、記録中、次を取得中、失敗を区別する。失敗時は現在の投稿を残し、次へ進んだように見せない。再試行は失敗した段階から行う。
- 残り件数は現在投稿を含む未閲覧数。自動または明示操作の記録成功時に減る。別端末の変更は次のサーバー取得で整合させる。
- 最後の記録と次の取得が成功し未閲覧0件なら「新しい投稿はここまでです」と表示し、タイムラインへ戻れる。全メディアを見たとは表現しない。
- ブラウザバック・途中離脱後はサーバー上の未閲覧から再開する。ローカル保存が使えなくても閲覧を止めない。

## 投稿カード

Media Gridの上には、小さなプロフィールアイコンと投稿者名を横並びにし、その下の独立した行へEvent titleと見出しを表示する。投稿者アイコンは投稿者名の文字と同程度の大きさに抑え、Event titleと見出しにはアクセントカラーを使わず、投稿者と投稿の分類を混同させない。TimelineではEvent titleと見出しを`Event title ＞ 見出し`の順に表示し、Event titleにはカレンダーアイコンを付ける。Eventと見出しのどちらもないPostでは分類の代替文言を表示しない。

Media Gridの下には「見た人」の両目アイコンと人数、コメントアイコン付きのComment導線を並べ、右側へ日付を表示する。狭い幅・文字拡大では補助情報行を折り返してよい。Comment導線は0件なら「コメントを書く」、1件以上なら「コメントN件」と表示する。撮影日時がある場合はカメラアイコンと撮影日、ない場合はアップロードアイコンと投稿日を表示し、読み上げでも日付の種類を区別する。Captionは入力項目名を毎回表示せず本文として読めるようにする。**目標仕様 #44:** 写真の直後にCaption、その次にコメント導線と日付・見た人を置き、写真と言葉の連続性を優先する。Commentがある場合は最新の1件をPost Cardに表示する。2件以上ある場合は、その下に「ほかのコメントを見る」を表示し、Post Detailへ移動できるようにする。総数はComment導線に表示済みのため、この導線では件数を重複表示しない。

目標の情報順（#44）:

| 順序 | 内容                       | 扱い                                           |
| ---- | -------------------------- | ---------------------------------------------- |
| 1    | 投稿者、イベント・見出し   | 投稿者名は維持し、分類を通常色で表示           |
| 2    | 写真・動画                 | カード幅を使う                                 |
| 3    | ひとこと                   | 存在する場合のみ本文として表示                 |
| 4    | コメント導線、日付、見た人 | コメントを見つけやすくし、日付・人数は補助情報 |
| 5    | 最新コメント、残りへの導線 | 同じ面で自然に続ける                           |

## Media Grid

1枚:

- 大きく1枚

2枚:

- 2分割

3枚:

- 大1 + 小2

4枚以上:

- 代表3枚 + `+N`

写真・動画をできるだけ大きく表示。

Post CardのMediaを押すと、Post Detailを経由せず、選択したMediaをMedia Viewerで直接開く。Media Viewerを閉じると、開く前のTimelineまたはEvent Detailへ戻る。投稿者とCaptionの導線はPost Detailを開く。**目標仕様 #47:** 「コメントを書く」は入力欄が見える状態、「コメントN件」「ほかのコメントを見る」はコメント一覧の開始位置を開く。入力欄への意図的な操作以外でキーボードを自動表示しない。

表示済みのthumbnailとpreviewは端末へ最大300件キャッシュする。originalとvideoに加え、アプリ本体のHTML、JavaScript、CSSはService Workerのキャッシュ対象外とし、ログアウト時にメディアキャッシュを削除する。PWA起動中は、HTMLの初期表示からアプリの起動と認証確認が完了するまで、背景透過のアプリアイコンとアプリ名を画面中央へ途切れず表示する。途中でspinnerだけの画面へ切り替えない。ブラウザでの読み込み中はアプリ名と読み込み状態を表示する。現行はService Worker更新時に新版へ切り替えて自動再読み込みする。**目標仕様 #51:** 未保存入力・選択ファイル・送信中の処理がある間は更新による再読込も保留し、保存完了または明示的な破棄後に更新する。

# Album

画面名のヘッダーは表示せず、年の前後移動と月タブを一体化して画面上部へ固定する。公開済みの写真・動画をイベント開始日（未設定なら終了日）の年月にまとめる。月・年をまたぐイベントは開始月へまとめ、重複表示しない。イベントなし・期間未設定の場合のみ撮影日時（Media、Post、公開日時、作成日時の順）の日本時間の日付を使う。APIもこの分類日、撮影日時、Media IDの降順でページングし、撮影日時そのものは変更しない。月の代表Mediaを大きく、そのほかを3列gridで表示する。月タブの左端には、その年の全Mediaを3列gridで表示するグリッドアイコンを置く。月タブには件数を表示しない。年月タブは画像ページから作らず、公開済み・アップロード済みMediaの全年月と件数を別途取得して初回から選択可能にする。選択月または年のMediaを直接60件ずつ取得し、末尾400px手前で自動追加読込する。失敗時は既存画像を残して再試行、IntersectionObserver非対応環境のみ手動ボタンを表示する。期間切替で通信を中止し、別期間の遅延レスポンスを混在させない。Viewerから戻ると選択期間の取得済み件数と位置を復元する。月/年切替中は年月タブを維持し本文だけ対応するSkeletonを表示する。選択色はBottom Navigationと同じテーマ別の色を使う。Mediaを押すとMedia Viewerを開き、月表示から開いた場合は同じ月、年グリッドから開いた場合は同じ年の表示中Mediaを、Postをまたいで前後移動できる。閉じるとアルバムへ戻る。ボトムナビではイベントの右に配置する。

# Event List

表示順は進行中、予定、日付未定、終了とする。進行中は終了日が近い順、予定は開始日が近い順、日付未定は更新が新しい順、終了は終了日が新しい順に並べる。進行中と予定のカードには状態バッジを表示する。

一覧では進行中と予定を「進行中・これから」、日付未定を「日付未定」、終了を「これまで」に分け、該当するEventがない区切りは表示しない。

現行はカード全体が16:9の写真背景。**目標仕様 #45:** 表紙画像の領域を16:9とし、下に文章を置ける高さ可変のカードにする。

ヘッダー右上にはイベント作成ボタンを置かず、絞り込みボタンを表示する。絞り込みはモーダルで行い、タイトル・メモのキーワード、イベント期間との重なり、進行中・予定・日付未定・終了の状態を組み合わせられる。適用中はヘッダーのボタンに条件数を表示する。イベント作成は共通の追加ボタンから行う。

下部へdark gradient。

**目標仕様 #45:** 写真上はタイトルと期間を基本とし、状態は進行中・予定だけ小さく示す。メモと写真・動画数は写真下の同じ情報面へまとめる。メモは最大2行のプレビュー、詳細では全文を表示する。文字拡大・長いタイトルではタイトルと期間も写真外へ逃がしてよい。明るい・暗い・細部の多い写真で読みやすさを確認する。

表示:

- Event title
- start/end date
- description
- 写真数
- 動画数

必要以上のmetadataは表示しない。

# Event Detail

Eventだけに絞ったTimeline。

上部:

- 大きなCover
- Event title
- dates
- 写真数
- 動画数
- Post数

Coverの文字には読める濃さの局所グラデーションを使い、投稿面との境界に意図しない細線を残さない。最下部を純黒にすることは必須にしない（#45）。

メモが入力されている場合は、Coverの次に全文を表示する。改行を保ち、長い文も省略しない。

Event Detailを開いたときは、遷移元のスクロール位置を引き継がず画面先頭から表示する。Coverは画面ヘッダーの下へ固定し、投稿一覧を手前の不透明なsurfaceとして配置する。スクロールすると、上端を角丸にした投稿一覧がCoverへ重なり、最終的にCoverを覆う。Cover画像自体は重なっている間も同じ位置を保つ。現行の最大8%拡大・5pxぼかしは、#52で軽さと写真の見やすさを比較して調整する。固定値は必須にしない。端末で動きを減らす設定が有効な場合は拡大とぼかしを行わない。

ヘッダー右上にはイベントを管理できるユーザー向けの編集ボタンだけを表示し、投稿追加ボタンは置かない。投稿追加は共通の追加ボタンから行い、投稿がない場合は空状態の「写真を追加」からこのイベントを指定したまま開始できる。見出しの管理はEvent Editへ集約する。

Event Detailで共通の追加ボタンから「写真・動画」を選んだ場合も、投稿の有無にかかわらず表示中のEventを投稿作成画面へ引き継ぐ。引き継いだEventは選択欄で確認・変更できる。存在しないEventがURLで指定された場合はEvent選択を解除し、その理由を入力欄付近へ表示する。

Event Editではタイトル、日付、メモ、見出し、カバーの変更を画面内へ一時保持し、保存前にAPIへ反映しない。いずれかが変更された場合だけ、設定画面と同じ「変更を保存」ボタンをBottom Navigationの上へスライドインさせる。保存時はすべての変更を一括して反映する。利用者向けの表記には`Media`ではなく「メディア」を使う。

見出しは一つの文字列として扱い、日と地名を別項目に分解しない。長い文字列の自然な折り返しは許容する。
Event DetailではTimelineと同じPost Cardの構造を使い、見出しによるグループ分けを設けない。投稿カードの情報順を共用し、Event titleはCoverと重複するため省略して見出しだけを補助情報として表示する。見出しにはイベント用のカレンダーアイコンを付けず、見出しがない場合は分類行自体を表示しない。

# Post Detail

TimelineまたはEvent DetailのPostを押したら、画面全体を覆うPost Detailを即座に右からスライドインさせる。データ取得は開くanimationと並行して行い、実データと同じ配置のSkeleton、読み込み結果、読み込みエラーをページ内で切り替える。読み込み中やエラー中も戻れるようにする。

戻るボタンを押したらPost Detailを右へスライドアウトさせ、animation完了後に遷移元のスクロール位置へ戻る。ページ上部には共通の画面タイトルを表示せず、戻るボタンと権限に応じた投稿メニューを配置する。背景暗転、ドラッグハンドル、下方向のドラッグ操作は設けない。

投稿者、Event、見出し、Media Grid、反応、撮影日、CaptionはTimelineと同じ視覚構造で表示する。小さな投稿者アイコンと投稿者名を横並びにし、その下の独立行へ通常色で`Event title ＞ 見出し`を表示する。Event titleにはカレンダーアイコンを付け、Eventと見出しのどちらもない場合は分類の代替文言を表示しない。

CaptionとComment一覧は同じsurface上に連続して配置し、背景色や太い帯で別の島に分けない。Comment一覧の開始位置は1pxの区切り線と余白で示す。

投稿内容とComment一覧だけをページ内でスクロールし、コメント投稿フォームは画面下端へ固定する。現在ユーザーのアイコン、コメント入力欄、送信ボタンを横並びにし、モバイルのsafe areaを確保する。キーボード表示中はフォームをキーボード直上に保ち、Comment一覧の末尾が隠れない余白をスクロール領域へ設ける。

表示:

- 見出し
- Event
- date
- uploader
- Media Grid
- caption
- seen by
- comments

コメントには本文、ユーザー名、日時に加えて、ユーザー名の左にプロフィール画像または表示名の先頭文字を使った丸いアイコンを表示する。

ownerとuploaderには右上に3点メニューを表示し、「編集」「削除」を配置する。編集ではEvent、見出し、Captionの変更に加え、写真・動画を追加・削除・ドラッグ＆ドロップで並び替えできる。並び替えた順序は保存後も維持する。写真・動画は合計30件まで、最低1件を残す。既存Mediaの削除は保存時に反映し、追加Mediaのアップロードに失敗した場合は失敗した項目だけ再試行できる。投稿自体の削除時は確認モーダルを表示し、写真・動画とコメントも削除されて元に戻せないことを明示する。投稿編集画面から見出しを新規作成でき、追加後はその見出しを選択した状態にする。

投稿とイベントの編集完了後は、編集画面を履歴に残さず元の詳細画面へ戻る。詳細画面の戻る操作で編集画面へ逆戻りさせない。

Mediaを押すとMedia Viewer。

# Media Viewer

写真・動画が主役。

- 大画面表示
- 前後移動
- `5 / 18`
- thumbnail strip
- 撮影日時
- uploader
- Event / 見出し / Post
- 保存

写真・動画は左右スワイプで前後へ切り替えられる。メディアは指の横移動に追従し、横移動が一定距離に達し、縦移動より明確に大きい場合だけ切り替える。切り替えに満たない場合は中央へ戻す。左右送りボタンとキーボードの左右キーでも、スワイプと同じ方向・速度の切り替えアニメーションを使う。動画上のタッチは再生操作を優先してスワイプ判定から除外する。先頭と末尾では抵抗を付け、それ以上移動しないことを示す。

閉じるボタン、現在位置、保存ボタンを含むヘッダーは画面上端へ固定し、Media Viewer内をスクロールしても表示し続ける。iOSのsafe areaを確保し、背後のMediaがヘッダー内へ透けない黒背景とする。

画像間の移動はブラウザ履歴へ追加しない。閉じる操作では実際の入口（タイムライン・イベント詳細・アルバム・投稿詳細）へ戻る。直接URLを開いて入口がない場合のみ対象Post Detailへ置き換えて戻す。その後の戻る操作でViewerへ逆戻りしない。

既存のViewerコメント導線は投稿のコメント欄を開く。コメントは写真単位ではなく投稿単位。#47ではこの導線と一覧からの導線を共通の遷移契約へ揃える。

**目標仕様 #50:** 動画の再生マークと長さの表示位置を一覧間で統一する。時間が未取得なら0秒とせず省略または取得中とする。読み込み中・再生可能・失敗は対象動画の近くで識別でき、失敗時に再試行できる。動画の自動再生は下記「写真・動画の閲覧（#56〜#61）」の明示操作・通信条件に従う。

外部共有ボタンは置かない。

# Post Create

順番:

```text

Event
見出し
ひとこと（Caption、任意）

```

Event / 見出しはoptional。

見出しはEvent選択時のみ。

見出しを新規作成でき、追加後はその見出しを選択した状態にする。投稿内容の各項目と投稿ボタンは24px、見出し選択と作成操作は同じまとまり内で12pxの縦間隔を設ける。注意文は入力欄と左端を揃える。見出し作成欄を負の余白で選択欄に重ねない。PCでは写真選択と投稿内容の2列構成を維持する。

写真は選択直後にローカルのObject URLで一覧へ表示する。動画も選択直後に準備中のプレースホルダーを追加し、サムネイルの生成完了後に画像へ切り替える。端末内では最大2件ずつ準備し、全件の完了を待たず完了した項目から反映する。動画は先頭のデコード済みフレームからサムネイルを生成し、動画のデコードは常に1件ずつ行う。写真と動画が混在する場合はそれぞれ1件まで並行する。準備中は各項目にspinnerを重ね、失敗した項目にはその場で再試行できる導線を表示する。

写真・動画はファイル選択に加えてドラッグ＆ドロップでも複数追加できる。PC幅ではドロップ領域を大きく表示し、ファイルを重ねている間は枠線と背景を変えて受付状態を示す。選択後はサムネイルとファイル名を確認でき、投稿開始前は個別に除外できる。非対応形式、0バイト、上限超過では対象ファイル名と理由を表示する。

ローカルでの準備中とアップロード中は区別し、進捗をヘッダー直下にsticky表示する。アップロード中に再試行ボタンを表示せず、失敗または中断した後だけ再試行導線を表示する。投稿編集で写真・動画を追加する場合も同じ表示と処理方式を使う。

不要:

```text
撮影日の扱い
写真・動画の撮影日時を...
```

これは内部仕様。

# Settings

最低限:

- 表示名
- LINE通知
- LINE連携状態
- アプリからの通知の受信状態
- メンバー一覧（ownerのみ。role・LINE通知ON/OFF）
- メンバーの管理（ownerのみ。権限設定・削除・招待URL発行画面への導線）
- ログアウト

LINE通知は、ベルアイコン、オン・オフの文言、状態に応じた説明を添えたトグルスイッチで切り替える。切り替え時はアイコンとスイッチをアニメーションさせるが、カード自体の背景色と枠線は変えない。「このごろ」のLINEアカウントを友だち追加していない場合は利用不可と明示する。アプリからの通知が受信可能な場合は状態だけを表示し、受信不可の場合だけLINEで「このごろ」アカウントをブロックしていないか確認するよう案内する。LINEでブロックするとWebhook受信後に受信不可・通知OFFへ自動更新し、友だち追加またはブロック解除後は受信可能へ自動更新する。解除時に通知を自動でONへ戻さず、ユーザーが明示的にONへ切り替える。

新着のLINE通知はテキスト形式とし、まとめた投稿の件数とMedia件数に加えて、batch内で最も新しく公開された投稿へのURLを表示する。写真・動画のサムネイルは通知に載せない。通知から開いた投稿でログインが必要な場合は、LINE Login完了後もその投稿へ戻す。

Bottom Navigationの5つ目は全role共通で歯車アイコンの「設定」とする。独立したメンバー画面は設けず、ownerの設定画面へメンバー一覧を統合する。「メンバーの管理」からさらに1階層下へ移動し、メンバーの権限設定・削除と招待URL発行を行う。削除前には、アクセスできなくなる一方で過去の投稿やコメントは残ることを確認画面で伝える。招待時の権限は、権限名と操作説明を含むカード型ラジオボタンから選択する。

設定項目は「プロフィール」「LINE」「表示」「使い方」「メンバー」「その他」の見出しとカードを共通構造として使用し、設定グループ全体を囲う外枠は表示しない。入力欄、選択肢、トグル、グループ内の区切りなど、操作対象や状態の識別に必要な境界は維持する。「使い方」では初回ガイドとホーム画面追加案内を再表示できる。表示名またはLINE通知が保存済みの値から変わった場合だけ、Bottom Navigationの上へ「変更を保存」ボタンをスライドインさせる。保存バーは追加ボタンより前面へ表示する。保存後はトーストを表示してボタンを収納する。選択時に即時反映するテーマ変更は保存ボタンの表示条件に含めず、テーマ設定は保存対象の項目より下へ分離する。テーマは比較しやすさを優先して3択カードを維持する。

設定項目の下部に背景透過のアプリアイコン、アプリ名、`package.json`を参照したバージョンを表示する。アプリ内でロゴを表示する場合は背景透過版を使用し、選択中のテーマに合わせて切り替える。ホーム画面へ登録するPWAアイコンはOS向けの背景付き画像を維持する。

# 戻る操作と閲覧文脈（目標仕様 #48）

| 詳細・Viewerを閉じる／ブラウザバック | 実際の入口の位置と条件を復元                       |

ピクセル位置だけでなく項目IDと条件を保持し、遅延読込後も可能な範囲で同じ項目へ復帰する。削除された項目は近傍へ、該当なしは条件を残した空状態へ戻す。表示データが変わっても無限に復元を試さない。端末間同期や長期の履歴保存は行わない。

# 投稿の離脱保護（目標仕様 #51）

- 未保存の入力・ファイル選択がある状態でアプリ内を離れる場合は、続ける／破棄して離れるを選べる。空のフォームや保存成功後には確認しない。
- ブラウザ終了・再読込の警告は環境上の制限があり保証しない。ファイルを再選択する必要がある場合を明確にし、保存していないデータを復元可能と案内しない。
- ローカル準備、送信中、送信済み、投稿の確定、失敗・中断を区別する。ファイルの送信完了だけで投稿完了と表示しない。
- 全体の件数と各項目の状態を対応させる。測定できない準備工程で架空のパーセントを表示しない。
- 再試行は失敗段階から行い、送信済み項目を重複させない。送信中の編集・除外・離脱の扱いを明確にする。
- 自動更新による再読込も同じ保護対象とする。永続的な動画保存やバックグラウンド送信保証は追加しない。

# 空状態・表示状態の共通契約

空状態はviewerへ投稿作成を勧めない。絞り込み結果0件は「投稿なし」と区別し、条件を解除できる。読み込み中・エラーでも閉じる／戻るは操作可能にする。追加読込の失敗は既存内容を残して末尾で再試行する。設定の保存済み・変更中・保存中・失敗を区別し、テーマの即時反映とLINE通知の保存確定を混同させない。


# 写真・動画の閲覧（#56〜#61）

写真と動画が混在する思い出を、自分のペースで気軽に鑑賞する。動画の割合は半数未満を想定し、種類による優先表示は行わない。写真、イベント単位の整理、既存の5タブ、投稿順、投稿単位の既読を維持する。動画の視聴完了と投稿の既読は別の意味とする。

- 一覧は登録順の写真・動画を共通グリッドに静止サムネイルで表示する。動画は再生マークと長さで識別でき、一覧では自動再生しない。
- 映像タップでViewerを開く。音付き自動再生がブラウザに拒否されたら明示的な再生ボタンで回復できる。
- Viewerは写真・動画の縦横の構図をcontainで保ち、常時閉じる、共通の前へ・次へ、サムネイル選択を提供する。移動は手動のみ。連続再生の切替は置かず、動画終了時は現在の項目に留まり、終了を明示する。末尾の次へは無効にする。
- 動画の終わり近くで直後の1件が動画の場合だけ、手動移動に備えて先読みする。写真を飛ばして動画を探さない。通信量に上限を設け、プレイヤーを大量に作らない。メタデータ取得、動画の冒頭準備、実際に先読みが効いたかは区別して検証する。
- 同一端末・ユーザーで再生位置を保持し、ログアウトや権限変更で別人の情報を引き継がない。履歴は件数を制限し、端末間同期は行わない。
- Viewer内で投稿のコメントを読んで書ける。動画単位のコメントと誤認させず、フォームを閉じたら鑑賞へ戻る。入力中は再生を止める。
- 再生用ファイルは任意。PC用の変換コマンドと取り込みで原本に対応付ける。作成・編集の双方で同じ手順を使い、原本は保存用に残す。
- 大きなファイルはR2へ分割して直接送信し、同じ画面での失敗再試行は送信済み部分を利用する。ページ終了後のファイル復元は保証しない。
- 一覧は必要な代表メディアと件数、最新コメントだけを取得する。全メディアと会話は詳細取得とし、部分配列の長さを全件数として表示しない。

性能はAPI時間、再生操作からplayingまで、bufferingの回数と待機時間で比較する。計測に写真・動画本体、署名URL、コメント、氏名を含めない。テスト素材と実機/実回線の測定を区別する。

## ログイン画面の案内

見出しは「日々のひとこまを、」「おすそわけ。」の間で明示的に改行する。説明文は `「この頃、何してるかな。」ふと気になる日々の様子が、招待された家族にだけ、そっと届きます。` とし、途中に明示改行を入れず、画面幅に応じて自然に折り返す。投稿者の思い出を親や家族へ届ける関係を伝え、全メンバーが投稿する印象や「夫婦」という直接的な呼称を避ける。
