# UI / UX Specification

## 共通

モバイルファースト。

主対象:

- 320px〜430px

PCでも使用可能だが、スマホUIを無制限に横へ引き伸ばさない。

画面ヘッダーは原則:

- 画面タイトル
- 必要なアクション

のみ。

説明サブタイトルは不要。

操作成功のうち、画面に残す必要がなく、遷移後には結果だけを短く伝えるものはトーストで表示する。対象は設定保存、投稿とイベントの作成・編集・削除、招待URLのコピーとする。入力エラー、読み込み失敗、削除確認はトーストにせず、操作箇所の近くまたはモーダルに表示する。コメントや権限変更のように結果がその場で明確に反映される独立操作にはトーストを表示しない。

データ取得中は、各画面の完成後の構造に近いSkeletonを表示する。画像やテキストの大きさを読み込み前から確保してLayout Shiftを抑え、共通の色とshimmer表現を使う。Skeletonの装飾要素は`aria-hidden="true"`とし、読み込み領域には`aria-busy="true"`と支援技術向けの読み込み中表示を設ける。`prefers-reduced-motion: reduce`ではshimmer animationを停止する。

## Bottom Navigation

```text
タイムライン
近況
イベント
アルバム
設定
```

「＋追加」はBottom Navigationから独立させ、そのすぐ上の画面右下へ固定表示する。ownerとuploaderが押すと「写真・動画」と「イベント」を選択できる。viewerには表示しない。

Bottom Navigationのタブを押して画面を切り替えたときは、遷移先を画面先頭から表示する。ほかのタブのスクロール位置は引き継がない。

# Activity

公開投稿とコメントを新しい順に表示する。誰が、どの投稿に、いつ操作したかを表示し、タップするとPost Detailを開く。投稿を表す名称はCaptionではなくScene titleを優先し、Sceneがない場合はEvent title、どちらもない場合は「投稿」とする。ownerには、リスト上部へ「最後に見た時間」として、メンバーのアイコン、表示名、最終閲覧からの相対時間を横並びで表示する。uploaderとviewerには最終閲覧時間を表示せず、APIからも返さない。閲覧行為は近況リストへ表示しない。近況は40件単位で取得し、末尾へ近づいたときに次の近況を自動で追加する。追加取得に失敗した場合は自動再試行を止め、既存の近況を残したまま再試行操作を表示する。

# Timeline

タイトル:

```text
タイムライン
```

Postは複数Mediaのまとまり。

現在のユーザーがまだ見ていないPostは、Media Grid上へ「未閲覧」バッジを表示する。Post Cardが自動既読になったらバッジを消す。

Media Gridの上には、小さなプロフィールアイコンと投稿者名を横並びにし、その下の独立した行へEvent titleとScene titleを表示する。投稿者アイコンは投稿者名の文字と同程度の大きさに抑え、Event titleとScene titleにはアクセントカラーを使わず、投稿者と投稿の分類を混同させない。TimelineではEvent titleとScene titleを`Event title ＞ Scene title`の順に表示し、Event titleにはカレンダーアイコンを付ける。EventとSceneのどちらもないPostでは分類の代替文言を表示しない。

Media Gridの下には「見た人」の両目アイコンと人数、コメントアイコンとComment総数を並べ、同じ行の右端へ日付を表示する。撮影日時がある場合はカメラアイコンと撮影日、ない場合はアップロードアイコンと投稿日を表示し、読み上げでも日付の種類を区別する。その下にCaptionを「ひとこと」として表示する。Commentがある場合は最新の1件をPost Cardに表示する。2件以上ある場合は、その下に「ほかのコメントを見る」を表示し、Post Detailへ移動できるようにする。総数はコメントアイコンの右に表示済みのため、この導線では件数を重複表示しない。

代表例:

```text
[投稿者アイコン] 翼
ドイツ旅行 ＞ Day 2
[ Media Grid ]

👀 3   ◯ 2                         📷 8月30日

念願のポルシェミュージアムへ行けた

[コメント者アイコン] すごかったね！
ほかのコメントを見る
```

## Media Grid

1枚:
- 大きく1枚

2枚:
- 2分割

3枚:
- 大1 + 小2

4枚以上:
- 代表3枚 + `+N`

写真・動画をできるだけ大きく表示。

Post CardのMediaを押すと、Post Detailを経由せず、選択したMediaをMedia Viewerで直接開く。Media Viewerを閉じると、開く前のTimelineまたはEvent Detailへ戻る。投稿者、Caption、Commentの導線はPost Detailを開く。

表示済みのthumbnailとpreviewは端末へ最大300件キャッシュする。originalとvideoに加え、アプリ本体のHTML、JavaScript、CSSはService Workerのキャッシュ対象外とし、ログアウト時にメディアキャッシュを削除する。PWA起動中は、HTMLの初期表示からアプリの起動と認証確認が完了するまで、背景透過のアプリアイコンとアプリ名を画面中央へ途切れず表示する。途中でspinnerだけの画面へ切り替えない。ブラウザでの読み込み中はアプリ名と読み込み状態を表示する。Service Worker更新時は新版へ切り替えて自動再読み込みする。

# Album

画面名のヘッダーは表示せず、年の前後移動と月タブを一体化して画面上部へ固定する。公開済みの写真・動画を撮影日時の新しい順にまとめ、月の代表Mediaを大きく、そのほかを3列gridで表示する。月タブの左端には、その年の全Mediaを3列gridで表示するグリッドアイコンを置く。月タブには件数を表示しない。選択色はBottom Navigationと同じテーマ別の色を使う。Mediaを押すとMedia Viewerを開き、閉じるとアルバムへ戻る。ボトムナビではイベントの右に配置する。

# Event List

表示順は進行中、予定、日付未定、終了とする。進行中は終了日が近い順、予定は開始日が近い順、日付未定は更新が新しい順、終了は終了日が新しい順に並べる。進行中と予定のカードには状態バッジを表示する。

各Eventカードの背景全面にCover Mediaを表示。

Eventカードの縦横比は16:9とする。

ヘッダー右上にはイベント作成ボタンを置かず、絞り込みボタンを表示する。絞り込みはモーダルで行い、タイトル・メモのキーワード、イベント期間との重なり、進行中・予定・日付未定・終了の状態を組み合わせられる。適用中はヘッダーのボタンに条件数を表示する。イベント作成は共通の追加ボタンから行う。

下部へdark gradient。

表示:

- Event title
- start/end date
- 写真数
- 動画数

必要以上のmetadataは表示しない。

# Event Detail

Eventだけに絞ったTimeline。

上部:

- 大きなCover
- Event title
- dates
- 写真数
- 動画数
- Post数

Cover下部のdark gradientは画像下端まで連続させ、最下部では画像色が線状に残らないよう完全な黒へ収束させる。

Event Detailを開いたときは、遷移元のスクロール位置を引き継がず画面先頭から表示する。Coverは画面ヘッダーの下へ固定し、投稿一覧を手前の不透明なsurfaceとして配置する。スクロールすると、上端を角丸にした投稿一覧がCoverへ重なり、最終的にCoverを覆う。Cover画像自体は重なっている間も同じ位置を保ち、スクロール量に応じて最大8%まで緩やかに拡大しながら、最大5pxまで徐々にぼかす。端末で視差効果を減らす設定が有効な場合は拡大とぼかしを行わない。

ヘッダー右上にはイベントを管理できるユーザー向けの編集ボタンだけを表示し、投稿追加ボタンは置かない。投稿追加は共通の追加ボタンから行い、投稿がない場合は空状態の「写真を追加」からこのイベントを指定したまま開始できる。Sceneの管理はEvent Editへ集約する。

Event Editではタイトル、日付、メモ、シーン、カバーの変更を画面内へ一時保持し、保存前にAPIへ反映しない。いずれかが変更された場合だけ、設定画面と同じ「変更を保存」ボタンをBottom Navigationの上へスライドインさせる。保存時はすべての変更を一括して反映する。利用者向けの表記には`Media`ではなく「メディア」を使う。

その下:

```text
Day 2 - シュトゥットガルト

Post Card
Post Card

Day 1 - フランクフルト

Post Card
```

Scene titleは必ず1行の文字列として扱う。
Event DetailではTimelineと同じPost Cardの構造を使い、Scene titleのグループ見出しを設けない。投稿者名と日付を最上位に表示し、Event titleはCoverと重複するため省略してScene titleだけを補助情報として表示する。Scene titleにはイベント用のカレンダーアイコンを付けず、Sceneがない場合は分類行自体を表示しない。

# Post Detail

TimelineまたはEvent DetailのPostを押したら、画面全体を覆うPost Detailを即座に右からスライドインさせる。データ取得は開くanimationと並行して行い、実データと同じ配置のSkeleton、読み込み結果、読み込みエラーをページ内で切り替える。読み込み中やエラー中も戻れるようにする。

戻るボタンを押したらPost Detailを右へスライドアウトさせ、animation完了後に遷移元のスクロール位置へ戻る。ページ上部には共通の画面タイトルを表示せず、戻るボタンと権限に応じた投稿メニューを配置する。背景暗転、ドラッグハンドル、下方向のドラッグ操作は設けない。

投稿者、Event、Scene、Media Grid、反応、撮影日、CaptionはTimelineと同じ視覚構造で表示する。小さな投稿者アイコンと投稿者名を横並びにし、その下の独立行へ通常色で`Event title ＞ Scene title`を表示する。Event titleにはカレンダーアイコンを付け、EventとSceneのどちらもない場合は分類の代替文言を表示しない。

CaptionとComment一覧は同じsurface上に連続して配置し、背景色や太い帯で別の島に分けない。Comment一覧の開始位置は1pxの区切り線と余白で示す。

投稿内容とComment一覧だけをページ内でスクロールし、コメント投稿フォームは画面下端へ固定する。現在ユーザーのアイコン、コメント入力欄、送信ボタンを横並びにし、モバイルのsafe areaを確保する。キーボード表示中はフォームをキーボード直上に保ち、Comment一覧の末尾が隠れない余白をスクロール領域へ設ける。

表示:

- Scene
- Event
- date
- uploader
- Media Grid
- caption
- seen by
- comments

コメントには本文、ユーザー名、日時に加えて、ユーザー名の左にプロフィール画像または表示名の先頭文字を使った丸いアイコンを表示する。

ownerとuploaderには右上に3点メニューを表示し、「編集」「削除」を配置する。編集ではEvent、Scene、Captionの変更に加え、写真・動画を追加・削除・ドラッグ＆ドロップで並び替えできる。並び替えた順序は保存後も維持する。写真・動画は合計30件まで、最低1件を残す。既存Mediaの削除は保存時に反映し、追加Mediaのアップロードに失敗した場合は失敗した項目だけ再試行できる。投稿自体の削除時は確認モーダルを表示し、写真・動画とコメントも削除されて元に戻せないことを明示する。投稿編集画面からSceneを新規作成でき、追加後はそのSceneを選択した状態にする。

投稿とイベントの編集完了後は、編集画面を履歴に残さず元の詳細画面へ戻る。詳細画面の戻る操作で編集画面へ逆戻りさせない。

Mediaを押すとMedia Viewer。

# Media Viewer

写真・動画が主役。

- 大画面表示
- 前後移動
- `5 / 18`
- thumbnail strip
- 撮影日時
- uploader
- Event / Scene / Post
- 保存

写真・動画は左右スワイプで前後へ切り替えられる。メディアは指の横移動に追従し、横移動が一定距離に達し、縦移動より明確に大きい場合だけ切り替える。切り替えに満たない場合は中央へ戻す。左右送りボタンとキーボードの左右キーでも、スワイプと同じ方向・速度の切り替えアニメーションを使う。動画上のタッチは再生操作を優先してスワイプ判定から除外する。先頭と末尾では抵抗を付け、それ以上移動しないことを示す。

閉じるボタン、現在位置、保存ボタンを含むヘッダーは画面上端へ固定し、Media Viewer内をスクロールしても表示し続ける。iOSのsafe areaを確保し、背後のMediaがヘッダー内へ透けない黒背景とする。

画像間の移動はブラウザ履歴へ追加しない。閉じる操作ではPost Detailへ戻り、その後の戻る操作でMedia Viewerへ戻らない。

外部共有ボタンは置かない。

# Post Create

順番:

```text
写真・動画
Event
Scene
ひとこと（Caption、任意）
投稿
```

Event / Sceneはoptional。

SceneはEvent選択時のみ。

Sceneを新規作成でき、追加後はそのSceneを選択した状態にする。

写真は選択直後にローカルのObject URLで一覧へ表示する。動画も選択直後に準備中のプレースホルダーを追加し、サムネイルの生成完了後に画像へ切り替える。端末内では最大2件ずつ準備し、全件の完了を待たず完了した項目から反映する。動画は先頭のデコード済みフレームからサムネイルを生成し、動画のデコードは常に1件ずつ行う。写真と動画が混在する場合はそれぞれ1件まで並行する。準備中は各項目にspinnerを重ね、失敗した項目にはその場で再試行できる導線を表示する。

ローカルでの準備中とアップロード中は区別し、進捗をヘッダー直下にsticky表示する。アップロード中に再試行ボタンを表示せず、失敗または中断した後だけ再試行導線を表示する。投稿編集で写真・動画を追加する場合も同じ表示と処理方式を使う。

不要:

```text
撮影日の扱い
写真・動画の撮影日時を...
```

これは内部仕様。

# Settings

最低限:

- 表示名
- LINE通知
- LINE連携状態
- アプリからの通知の受信状態
- メンバー一覧（ownerのみ。role・LINE通知ON/OFF）
- メンバーの管理（ownerのみ。権限設定・削除・招待URL発行画面への導線）
- ログアウト

LINE通知は、ベルアイコン、オン・オフの文言、状態に応じた説明を添えたトグルスイッチで切り替える。切り替え時はアイコンとスイッチをアニメーションさせるが、カード自体の背景色と枠線は変えない。「このごろ」のLINEアカウントを友だち追加していない場合は利用不可と明示する。アプリからの通知が受信可能な場合は状態だけを表示し、受信不可の場合だけLINEで「このごろ」アカウントをブロックしていないか確認するよう案内する。LINEでブロックするとWebhook受信後に受信不可・通知OFFへ自動更新し、友だち追加またはブロック解除後は受信可能へ自動更新する。解除時に通知を自動でONへ戻さず、ユーザーが明示的にONへ切り替える。

Bottom Navigationの5つ目は全role共通で歯車アイコンの「設定」とする。独立したメンバー画面は設けず、ownerの設定画面へメンバー一覧を統合する。「メンバーの管理」からさらに1階層下へ移動し、メンバーの権限設定・削除と招待URL発行を行う。削除前には、アクセスできなくなる一方で過去の投稿やコメントは残ることを確認画面で伝える。招待時の権限は、権限名と操作説明を含むカード型ラジオボタンから選択する。

設定項目は「プロフィール」「LINE」「表示」「メンバー」「その他」の見出しとカードを共通構造として使用する。表示名またはLINE通知が保存済みの値から変わった場合だけ、Bottom Navigationの上へ「変更を保存」ボタンをスライドインさせる。保存バーは追加ボタンより前面へ表示する。保存後はトーストを表示してボタンを収納する。選択時に即時反映するテーマ変更は保存ボタンの表示条件に含めず、テーマ設定は保存対象の項目より下へ分離する。テーマは比較しやすさを優先して3択カードを維持する。

設定項目の下部に背景透過のアプリアイコン、アプリ名、`package.json`を参照したバージョンを表示する。アプリ内でロゴを表示する場合は背景透過版を使用し、選択中のテーマに合わせて切り替える。ホーム画面へ登録するPWAアイコンはOS向けの背景付き画像を維持する。
