# このごろ — デザインガイド

## 適用範囲

このごろ固有の視覚・操作基準。旧ブランド参考資料のoverrideではなく本書を正本とする。2026-09の改訂は目標基準であり、アプリへの適用は #44〜#52 で段階的に行う。文書のマージだけで画面変更済みとは扱わない。[改訂記録](11_DESIGN_REVISION.md)を参照。

## 0. 美しさと触り心地を設計する

「思い出に触れる道具」を全画面の目標にする。見やすさの達成に加え、静止画としての構図、触りたくなる質感、機能固有の表情、操作前後の連続性を設計・レビューする。#111の改訂は後続実装の目標であり、既存の権限・データの意味・操作契約を変えない。

温かい白と写真を軸に、柔らかな陰影、面の重なり、厚みのある部品、黄色いしおりで世界観を作る。全画面を同じ平面カードへ揃えない。読む場面は安定させ、開く・並べる・届ける場面には印象に残る動きを付ける。装飾の撤去を第一解にせず、情報の配置・背景・動きの範囲を調整して魅力と操作性を両立する。

## 1. 情報の強弱

映像・写真 → 見出し・ひとこと → 操作 → 投稿者・日付・閲覧人数の順に視覚的な重みをつける。これは視覚的優先順位であり、読み上げ順や全画面のDOM順を一律に固定する指定ではない。

- コメントを書く導線は見つけやすくするが、閲覧人数は強調しない。
- 一つの領域を区切る際は余白を先に使い、必要なら面の差、最後に細い線を使う。
- 投稿全体を一つのまとまりとし、写真とコメントをさらにカードで囲わない。
- 空の分類や重複するメタ情報を表示しない。機能要件で必要な情報は隠さず、まとめ方を改善する。
- ヘッダーは画面タイトルと必要な操作。目的を繰り返すサブタイトルは付けない。

## 2. 色と面

下表は #52 で適用する目標値。既存CSS変数を意味で対応づけ、同じ役割の色を画面ごとに増やさない。

| 役割           | ライト    | ダーク    | 用途                                       |
| -------------- | --------- | --------- | ------------------------------------------ |
| canvas         | `#F7F7F5` | `#141416` | ページ背景                                 |
| surface        | `#FFFFFF` | `#202023` | 投稿・設定・入力の基面                     |
| surface-muted  | `#EFEFEC` | `#2B2B2F` | 入力補助・控えめな面の差                   |
| text-primary   | `#242424` | `#F5F5F3` | 見出し・本文                               |
| text-secondary | `#62625F` | `#B8B8B2` | 日付・補助情報                             |
| separator      | `#DDDDD7` | `#3B3B40` | 装飾的な区切り。入力境界の視認性は別途確認 |
| accent         | `#FFD166` | `#FFD166` | 主操作の背景                               |
| on-accent      | `#1F2733` | `#1F2733` | 黄色上の文字・アイコン                     |
| accent-ink     | `#6B4B00` | `#FFD166` | リンク・選択中のアイコンとラベル           |
| viewer         | `#000000` | `#000000` | 写真・動画ビューワー                       |

選択中のボトムナビと年月タブはaccent-inkを共用し、太さ・現在位置の読み上げでも識別する。選択状態には小さな印や局所的な面を使え、印の移動とアイコンの線・塗りで切替を表す。黄色を白背景上の小さな文字へ直接使わない。

成功・警告・削除の色は意味のための例外。色だけで伝えず文言とアイコンを添える。LINEブランドの表示と、アプリの通知状態色は混同しない。

写真そのものに色調補正やテーマ色のフィルターをかけない。写真上の文字は局所的な暗いグラデーションで支え、それでも読みにくい長文は写真外へ出す。画像下端を必ず純黒にする指定は設けない。

システム・ライト・ダークの選択と端末内保存を維持する。半透明のナビは背面が明暗の写真でも文字が読めること。不確実な場合は不透明にする。

## 3. 日本語の文字組み

システムフォントを使用し、SF Proを同梱しない。日本語に負の字間や細字300を一律指定しない。字間はnormal、本文は400、見出しと操作は600を基本とする。

| 役割                   | 基準サイズ       | 行高 | 備考                                           |
| ---------------------- | ---------------- | ---- | ---------------------------------------------- |
| 画面タイトル           | 24px（21〜28px） | 1.35 | 通常ヘッダーの基準。表紙・年月は別途構図を設計 |
| イベント・投稿の見出し | 18〜20px         | 1.45 | 写真を押しのける高さにしない                   |
| 本文・コメント         | 17px             | 1.6  | 内容を読む中心                                 |
| 入力・主要操作         | 16〜17px         | 1.5  | ラベルを省略しない                             |
| 日付・投稿者・補助文   | 14〜15px         | 1.5  | 薄くしすぎない                                 |
| ナビ・写真の枚数等     | 12〜13px         | 1.4  | 短い固定ラベルだけの例外                       |

表紙・年月・ログインの主見出しでは、通常ヘッダーと異なる文字の大小や太さを設計できる。イベント名は太字を基本とする。実装はrem等で文字拡大を尊重する。共通ヘッダーはUI・UX仕様の1行省略を維持し、詳細の本文見出しは自然に折り返す。複数行省略は一覧のプレビューに限定し、詳細では全文を読めるようにする。操作・エラー・重要な状態は省略しない。

## 4. 余白・角丸・アイコン

- 余白は4、8、12、16、24、32、48pxを基本とする。アイコンとラベルは8px、関連情報は8〜12px、投稿内は16px、独立したまとまりは24〜32pxを出発点にする。
- スマホの左右は16pxを基本にし、写真グリッドはカード内の追加余白を設けない。320pxで文字拡大時は固定横並びをほどく。
- カード16px、独立画像・入力・通常ボタン12px、小バッジ8px、人物アイコンとページインジケーターは真円。カード内の画像は外側の角だけ継承し、内側へ二重の角丸を作らない。
- 既存の主ボタンの丸薬形は許容する。通常ボタンまで丸薬形へ揃える必要はなく、同じ役割で統一する。
- カード、写真の重なり、主ボタン、浮いたメニューには、素材と高さを伝える柔らかな影を使う。静置・押下・持ち上げの差を共通化し、ダークでは縁の光と面の差も使う。全カードへ同じ影を一律適用せず、役割に合わせて設計する。
- Lucideの既存アイコンを基本に、同じ役割は同じサイズ・線幅へ揃える。基準20〜24px、線幅2。既存の「見た人」の両目アイコンとアプリアイコンは固有表現として維持する。
- タップ領域は44×44px以上。絵自体を44pxに拡大する必要はない。アイコンのみの閉じる・戻る・保存にもアクセシブル名を付ける。
- キーボードフォーカスは控えめな単一リングで明瞭に示す。二重リング・クリップ・単なる非表示を避ける。

## 5. 写真とレイアウト

- タイムラインは読む順序が崩れない1列。PCは本文列をおおむね640〜760pxに抑え、残りを補助領域や余白に使う。空の補助カードで埋めない。
- 1024pxから左ナビ。1024〜1199pxは無理に多列化せず、1200px以上で用途に応じた列を使う。全体キャンバスは最大1280pxを維持する。
- イベント一覧は表紙を比較できるグリッド、投稿作成はファイル確認と入力の2列、投稿詳細は写真と会話の2列。狭い幅や文字拡大では1列へ戻せる。
- 写真の比率は読込前に確保する。一覧は切り抜き可能、Viewerは全体を見られるcontain表示を基本とする。
- イベント表紙の画像領域は16:9を維持し、カード全体の高さは文章のために伸びてよい。詳細カバーは最初の投稿へ容易に進める高さにする。
- 自動カバーを基本とし、手動変更と表示位置調整で主題を救えるようにする。AI選別や顔認識は使わない。
- 動画の長さや枚数は同じ位置・同じ処理で表示し、写真上のバッジを増やしすぎない。

## 6. 動きと状態

押下は100〜160ms、通常の切替は180〜240ms、表紙の展開など象徴的な遷移は240〜360msを試作の初期値とする。時間は上限や合格値ではなく、移動距離と実機の手触りで調整する。同じ操作のテンポを揃え、指のスワイプ・ドラッグには即座に直接追従する。演出完了まで通信開始や次の操作を待たせない。

| 操作の意味       | 動きの設計                                                         |
| ---------------- | ------------------------------------------------------------------ |
| 開く・見る       | 押した写真・表紙が詳細の同じ要素へ広がる                           |
| 閉じる・戻る     | 元の項目と閲覧位置へ収まる。入口がない直リンクでは短い切替を使う   |
| 選ぶ             | 印が定着し、つまみやアイコンが役割に応じて変化する                 |
| 並べる           | 対象が持ち上がり、周囲が場所を空け、離すと収まる                   |
| 届ける・保存する | 実際の処理状態を伝え、成功後に投稿・会話・メンバーの定位置へ加わる |

イベントの開閉、写真の並び替え、投稿完了は象徴的な表現を作る。ナビやスイッチは短い反応、入力や長文閲覧は安定した面とする。スクロールのたびの登場演出や待機中の装飾ループは標準にしない。ベルなど一度の反応は明示操作を起点とし、切替の連打・中断では現在の操作へ追従する。

### 操作フィードバック（#99）

操作の意味に合わせ「押すと少し沈む」「つかむと持ち上がる」「選択・完了が分かる」を共通化する。押した瞬間から反応し、演出終了を待って遷移や送信を開始しない。押下中と選択済み・保存済みは別の状態として表現する。

| 対象                                 | 視覚表現の基準                                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 通常・アイコンボタン                 | 押下中だけ控えめに縮小し、離すと戻す。小さい操作ほどやや明確にする                                                 |
| イベント・アルバムのカード、メディア | ボタンより小さな縮小幅で沈ませる。画像を暗くするフィルターや大きな跳ね返りを加えない                               |
| 行・テキストリンク                   | 面や文字色・下線を控えめに変える。長文や入力欄全体を伸縮させない                                                   |
| ナビ・タブ・ラジオ・スイッチ         | 押下反応に加え、選択した印・文字・つまみの変化を残す。ナビの小さな印、通知ベル、テーマ見本など機能固有の表情を使う |
| 並び替え                             | 成立時に対象のみ少し拡大し影を付け、直接追従する。配置確定・キャンセル後は元の大きさへ戻す                         |
| 保存・送信成功                       | 既存のその場の反映またはチェック付きの完了表示。失敗に成功演出を付けない                                           |

縮小はレイアウト寸法を変えず、周囲の要素やスクロール位置を動かさない。入れ子の操作は実際に押した最も内側の対象だけを反応させる。ドラッグ・スワイプ・ズームに用いる変形を共通の押下演出で上書きしない。ホバー表現はマウス等のホバー可能な端末に限定し、タッチ後に残さない。

イベント詳細の表紙へ投稿面が重なる既存表現は維持する。スクロール連動の8%拡大・5pxぼかしは必須値から外し、#52で効果を比較する。奥行きの魅力、写真の見え方、スクロール性能を試作で比較し、範囲と強度を調整する。固定値の踏襲や一律撤去を判断の代わりにしない。ユーザーの明示的な演出指示が確認できる場合はそれを尊重する。

動きを減らす設定（`prefers-reduced-motion: reduce`）では自動的なスライド・拡大・ぼかし・shimmerを止め、色・印・文言で状態の変化を即時に伝える。指に直接追従する並び替えやスワイプの操作は維持し、装飾的な拡大や戻りのアニメーションを加えない。動きは情報や操作の前提にしない。

| 状態     | 表示と回復                                                     |
| -------- | -------------------------------------------------------------- |
| 初回読込 | 完成形に近いSkeleton。戻る・閉じるは操作可能                   |
| 追加読込 | 既存内容を残し末尾だけ読込状態にする                           |
| 空       | 短い説明と権限に合った次の操作。viewerに投稿を勧めない         |
| 処理中   | 対象操作の近くへ状態を表示し二重実行を防ぐ                     |
| 成功     | その場の反映で分かる場合はトーストを重ねない                   |
| 失敗     | 対象・理由・回復操作を同じ場所に出し、入力と成功済み項目を残す |

レイアウト変更とSkeleton更新は同じPRで行う。実画面と列・余白・画像比率を決めるCSSを共用し、管理者・投稿者・閲覧者の権限差も同じ判定で再現する。特にPCの補助列、設定・管理画面、画像と会話の配置を照合する。未取得の投稿所有者・件数・画像比率を確定情報として表示しない。

### 性能と遷移の成立

変形と透明度を中心に実装し、大面積のぼかしや多層の常時アニメーションは実機で負荷を確認する。画像の取得量や動画の自動再生を演出のために増やさない。未取得画像は比率を確保し、準備できた時点で置き換える。対応しないブラウザ、元の項目の削除、直リンクでは通常遷移へ戻せること。送信・保存・承認の成功演出はサーバーの成功確認後に行い、共有先への到着や端末保存の完了を推測で表さない。

## 7. 変更の確認基準

- 静止画で、写真の主役感、文字の強弱、面の重なり、ライト／ダークの素材感をレビューする。「整っている」だけで完了にしない。
- 動画または触れる試作で、機能固有の表情、操作前後の連続性、待たされないテンポ、繰り返し操作時の気持ちよさを確認する。
- 最初にイベント開閉・写真並び替え・LINE通知切替を試作し、鑑賞・作業・設定で共通する世界観を確かめる。録画で代替できない実機事項は未確認とする。

- 個人情報を含まない同じサンプルで変更前後を比較する。縦横写真、動画のみ、混在、長文、空、読込失敗を含める。
- 320px・390px前後・PC幅とライト／ダーク、200%文字拡大で、主要操作が隠れず横スクロールを強制しないことを確認する。
- プロジェクトの合格目標として、本文と補助文字は背景に対して4.5:1以上、操作識別に必要な境界・アイコンは3:1以上を確認する。写真上は代表写真で測る。装飾的区切り線は操作境界と区別する。
- タップ・キーボード・読み上げの基本操作、iPhoneのsafe areaとキーボード、PCの列幅と固定要素の重なりを確認する。
- 自動テストは変更の具体的な回帰リスクに絞る。色定数や文書をそのまま写すテストは追加しない。CIの既存ゲートは維持する。
- 実機確認していない事項は未確認と記録し、仕様の記載を実装済みの証拠にしない。

## 8. 写真・動画共通の鑑賞（#56・#60）

タイムラインは写真と動画を同じグリッドに登録順で並べる。動画だけを大きく優先表示せず、静止サムネイル・再生マーク・長さで内容を判断できるようにする。一覧の自動プレビューは行わない。

Viewerは写真と映像を広く取り、縦横の構図をcontainで保つ。常時閉じる・前/次を44px以上の操作領域で提供する。動画終了後も現在の項目に留まり、連続再生のボタンは置かない。読み込み中でも操作でき、コメントを閉じて同じ項目へ戻れる。200%文字拡大、safe area、動きを減らす設定を維持する。

## ヘッダーとナビの透け感（#135）

共通ヘッダー・タイムラインの年月見出し・アルバムの年月ヘッダー・ナビゲーションは背景色45%と透明55%を混ぜ、24pxのブラーと150%の彩度で背面の写真や色が透ける面にする。文字・アイコンの不透明度は維持する。ライト／ダークともsurface色を使う。透明度を下げる設定・高コントラスト設定・ブラー非対応時は不透明の面へ戻す。
