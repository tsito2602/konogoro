# 再生用動画の準備（任意）

通常の写真・動画の追加はそのまま利用できる。再生用動画を付けた場合は閲覧に軽いMP4を使い、ダウンロードは元ファイルを返す。R2 private bucketを維持し、有料の変換サービスは追加しない。

## PCで準備する

PCにNode.js、ffmpeg、ffprobeを用意し、このリポジトリで実行する。ffmpegのlibx264とAACエンコーダーが必要。元動画は1本500MB以下、1回30本まで。

```sh
node scripts/prepare-videos.mjs --output "/path/to/new-prepared-folder" "/path/to/clip1.mp4" "/path/to/clip2.mov"
```

出力先は未作成のフォルダを指定する。既存フォルダへの実行は上書きを防ぐためエラーにする。変換に失敗した場合も元動画は変更しない。失敗した出力先とは別の新しいフォルダを指定して再実行できる。

出力はH.264、yuv420p、30fps、AAC（元音声がある場合）、横1920×1080／縦1080×1920以内のMP4。小さい元動画を拡大しない。faststartで再生開始に必要な情報を先頭へ配置する。CRF 23、最大5Mbpsを目安にするため、必ず元動画より小さくなる保証はない。変換は元動画の長さ・PC性能に応じて時間がかかる。HDR映像の色調整は含まないため、HDR素材はSDRへ調整した映像を使用する。

## アプリで取り込む

1. 「写真・動画を追加」または投稿編集で、元動画を通常どおり選択する。
2. 「再生用動画を取り込む（任意）」を押し、出力フォルダ内の`konogoro-videos.json`とMP4をすべて選択する。
3. 対応確認が終わったら投稿・保存する。元動画と再生用動画の両方を送信する。

同名の別動画との取り違えを防ぐため、元動画・再生用動画のSHA-256と容量をブラウザで確認する。確認はWorker内で1MiBずつ読み、動画全体をメモリへ読み込まない。R2確定APIでは投稿権限・元動画の登録情報・送信対象を検証し、元動画と再生用動画の存在、容量、再生用のContent-Typeを確認する。R2上の全バイトをWorkerで再ハッシュしたり、Workerで動画変換したりはしない。

確認済みの再生用動画だけを配信に使用する。途中失敗時は元動画を維持し、同じ画面から再試行できる。「送信を中断」で進行中の送信を止められる。再読み込みした場合はファイルを選び直す必要がある。

既存の投稿はそのまま元動画で再生できる。今回の取り込みは新たに追加する動画が対象で、既存の元動画へ後から再生用動画だけを付ける操作は含めない。既存データのSHA-256を推定して紐付けることはしない。

## 検証

`npm run test -- src/worker/prepare-videos.test.ts`はffmpeg/ffprobeがある環境で合成動画を実際に変換し、H.264/AAC、横・縦の上限、無音、faststart、元動画保持、出力先上書き禁止を確認する。ffmpegのない環境ではこの2ケースをskipする。ブラウザの対応確認と確定APIの権限・失敗・再試行は通常のVitestで常に実行する。
