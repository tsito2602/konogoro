# このごろ — デザインの考え方

このごろは、家族の近況を写真と短い言葉で見返す場所。目指すのは、写真日記の親しみと、使い慣れた道具の分かりやすさを持つ画面である。

## 判断の軸

1. 写真の内容が最初に目に入り、次に見出しとひとことが読める。
2. 次の操作と、操作した結果が説明なしでも分かる。
3. 写真を閉じても、見ていた場所を失わない。
4. 文字を小さく・薄くして整えず、情報の優先順位と余白で静かにする。
5. 旅行写真も普段の写真も似合う、ほぼ無彩色の器にする。朝日の黄色は操作の意味に使う。

## このごろらしい画面

| 画面         | 視覚と体験の中心                         |
| ------------ | ---------------------------------------- |
| タイムライン | 大きな写真とひとことが続く写真日記       |
| イベント一覧 | 表紙の写真と題名で選べるフォトブック     |
| イベント詳細 | 表紙から投稿へ自然につながる旅行アルバム |
| アルバム     | 年月から写真そのものを探す一覧           |
| 投稿詳細     | 写真の続きに家族の会話がある場所         |
| 設定・投稿   | 状態と次の操作が明確な道具               |

画面タイトル下の定型サブタイトル、評価・競争を促す数字、写真を飾るためのイラストは追加しない。案内・エラー・入力補助は必要な箇所で短く伝える。

## 文書の役割

- 本書: 判断の軸。数値や画面仕様は重複定義しない。
- [デザインガイド](05_DESIGN_GUIDE.md): 色・文字・余白・部品・動き・確認基準の正本。
- [UI・UX仕様](04_UI_UX_SPEC.md): 画面ごとの情報・操作・状態・遷移の正本。
- [機能要件](01_REQUIREMENTS.md): 権限・データの意味・機能範囲の正本。
- [改訂記録](11_DESIGN_REVISION.md): 現行との差分、変更理由、後続Issueへの適用順。
- [旧参考資料](DESIGN_REFERENCE.md): 初期検討の保存資料。規範ではない。

ユーザーの明示指示を優先する。文書の役割を越えた矛盾は、適当に一方を選ばず関連文書を一緒に修正する。Appleの販促サイトに由来する青、巨大な見出し、負の字間、サイドバー禁止、全ボタンの丸薬形強制は採用しない。
